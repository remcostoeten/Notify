A toast has a **surface** and up to six **slots**. The surface is 400px wide, has a 12px radius, a hairline ring and a soft shadow, and picks a **tone**. The slots sit inside it in a fixed layout.

<ToastPreview example="message" trigger={false} />

| Slot        | Input field                | Part                         | Notes                                          |
| ----------- | -------------------------- | ---------------------------- | ---------------------------------------------- |
| Media       | `icon`, `avatar`, `status` | `Toast.Icon`, `Toast.Avatar` | Left of the text. An avatar replaces the icon. |
| Title       | `title`                    | `Toast.Title`                | First line, semibold.                          |
| Meta        | `meta`                     | `Toast.Title meta`           | Muted text after a divider, on the title line. |
| Description | `description`              | `Toast.Description`          | Wraps at about 71% of the toast width.         |
| Progress    | `progress`                 | `Toast.Progress`             | An 8px bar, with an optional label under it.   |
| Actions     | `actions`                  | `Toast.Actions`              | Text links or buttons, under everything else.  |
| Close       | `close`                    | `Toast.Close`                | A 24px button in the top right corner.         |

## Two ways to fill the slots

Pass the slots as one object and Notifier lays them out:

```tsx
notify({
  avatar: { src: sienna.src, badge: "online" },
  title: "Sienna Hewitt",
  meta: "2 mins ago",
  description: "I’ve finished adding my notes.",
});
```

Or compose the parts yourself when the layout is different. Both produce the same markup and use the same tokens.

```tsx
notify.custom(() => (
  <Toast>
    <Toast.Avatar src={sienna.src} badge="online" />
    <Toast.Body>
      <Toast.Title meta="2 mins ago">Sienna Hewitt</Toast.Title>
      <Toast.Description>I’ve finished adding my notes.</Toast.Description>
    </Toast.Body>
    <Toast.Close />
  </Toast>
));
```

See [Custom toasts](/docs/guides/custom-toasts).

## Tone

`tone` is `"light"` or `"dark"` and belongs to each toast, so a dark toast can sit on a light page. Set a default on `Notifier` with its `tone` prop, which also accepts `"auto"` to follow `prefers-color-scheme`.

## Status and icons

`status` is `"success"`, `"error"`, `"warning"`, `"info"` or `"loading"`. It picks the glyph and its color, and has two more effects: `loading` keeps the toast open, and `error` and `warning` are announced as alerts.

An icon has a **shape**:

| Shape    | Looks like                                     | Slot size |
| -------- | ---------------------------------------------- | --------- |
| `bare`   | The glyph alone, colored by the status.        | 20px      |
| `ring`   | The glyph with two concentric rings around it. | 20px      |
| `box`    | A 36px bordered square.                        | 36px      |
| `circle` | A 28px circle tinted with the status color.    | 28px      |

A status toast uses `bare`: a 20px glyph on the title line whose stroke carries the status color, and so does a loading toast, so the text does not move when a loading toast becomes a success toast. A custom icon element uses `box`. `ring` and `circle` are opt-in. The rings of `ring` are drawn outside its 20px slot, so they do not push the text.

When the status changes, the old glyph fades and shrinks out while the new one fades in, so a loading toast that settles reads as one mark becoming another.

## Actions

An action is a text link, an outline button or a filled button, in a default, muted or accent color. Text actions have no padding and sit flush with the text, so they take 20px of height. Buttons take 34px.
