# @remcostoeten/notifier - AI integration guide

Use this file as the source of truth when installing or using `@remcostoeten/notifier`.
It is a client-side React toast library. A toast is a surface with slots (icon or avatar,
title with meta, description, progress, actions, close). Content is passed to `notify` as an
object, or rendered from the `Toast` primitives through `notify.custom`.

## Requirements and installation

- React and React DOM 18 or newer
- `motion` 12 or newer (the package imports `motion/react`; do not install `framer-motion`)
- TypeScript is supported but not required

```bash
bun add @remcostoeten/notifier motion
npm install @remcostoeten/notifier motion
pnpm add @remcostoeten/notifier motion
yarn add @remcostoeten/notifier motion
```

There is no stylesheet to import. `Notifier` adds one `<style>` element to the document head
(pass `nonce` under a strict CSP, and `layer` to put it in a cascade layer). The font is `Inter`
when the page loads it, then the system font stack. Override it with `theme.font`.

## Setup

Mount exactly one `<Notifier />` near the application root. Calls to `notify` run in client
code, such as an event handler or a Client Component.

```tsx
// app/layout.tsx
import { Notifier } from '@remcostoeten/notifier'

export default function RootLayout({ children }: { children: React.ReactNode }) {
    return (
        <html lang='en'>
            <body>
                {children}
                <Notifier position='bottom-right' />
            </body>
        </html>
    )
}
```

## notify

`notify` returns the toast id (a string). Every function below is a property of `notify`.

| Call | Behavior |
| --- | --- |
| `notify(title, input?)` | Open a toast. `title` is a string. `input` is any `ToastInput` field |
| `notify(input)` | Open a toast from a `ToastInput` object |
| `notify.success(title, input?)` | Same with `status: 'success'`. Also `error`, `warning`, `info`, `loading` |
| `notify.update(id, patch)` | Merge a `ToastPatch` into an open toast |
| `notify.dismiss(id?)` | Close one toast, or every toast without an id |
| `notify.promise(promise, messages)` | Loading toast that becomes a success or error toast |
| `notify.custom(render, options?)` | Render your own content. `render` receives `{ id, tone, dismiss, update }` |

Passing an `id` that is already open replaces that toast's content and restarts its timer
instead of opening another. Nothing from the earlier call carries over, so use `notify.update`
to change only some fields. An `id` that is closing reopens with the new content. `update` on an
unknown or closing id does nothing.

## ToastInput

All fields are optional.

| Field | Type | Notes |
| --- | --- | --- |
| `title` | `ReactNode` | First line, semibold |
| `meta` | `ReactNode` | Muted text after a divider, on the title line |
| `description` | `ReactNode` | Body text. Wraps at about 71% of the toast width |
| `status` | `'success' \| 'error' \| 'warning' \| 'info' \| 'loading'` | Adds a status icon. See Status |
| `icon` | `IconConfig \| ReactElement` | `{ shape?, status?, node? }`. A bare element is placed in a box |
| `avatar` | `AvatarConfig` | `{ src?, alt?, fallback?, badge?, shape? }`. Replaces the icon |
| `progress` | `number \| { value: number \| null, label?: boolean \| ReactNode }` | 0 to 100. `null` is indeterminate. A number shows a percentage label |
| `actions` | `ActionConfig[]` | See Actions |
| `close` | `boolean` | Close button. Default `true` |
| `tone` | `'light' \| 'dark'` | Default is the `Notifier` tone |
| `width` | `number \| string` | Default 400px |
| `animateNumbers` | `boolean` | Default is the `Notifier` setting. See Number animation |
| `className`, `style` | `string`, `CSSProperties` | Root element |
| `classNames` | `Partial<Record<ToastSlot, string>>` | Slots: root, icon, avatar, badge, body, title, meta, description, progress, label, actions, action, aside, close |
| `id` | `string` | Generated when omitted |
| `position` | `ToastPosition` | Default is the `Notifier` position |
| `duration` | `number` | Milliseconds. `0` keeps the toast open. See Duration |
| `swipe` | `boolean` | Default is the `Notifier` setting |
| `onOpen`, `onDismiss`, `onClose` | `(id) => void`, `(id, reason) => void`, `(id) => void` | `onClose` fires after the exit animation |

Dismiss reasons: `timeout`, `swipe`, `close`, `action`, `manual`, `replaced`.

### Status

`status` picks the glyph and color of the icon. Every status, loading included, defaults to
the `bare` shape, so the text does not move when a loading toast becomes a success toast.
A status change crossfades the glyph: the old one shrinks out, the new one fades in.
`error` and `warning` are announced as alerts, the rest politely. A custom icon with no
status defaults to the `box` shape.

### Number animation

With `animateNumbers` on `Notifier` or on one toast, every number in the title, meta, description,
progress label and actions aside rolls digit by digit when an update changes it. Digits roll up when
the number grows and down when it shrinks, and a digit added on the left slides in. It needs no
extra package: the effect is plain DOM and the Web Animations API, and it is off by default. It
reads text and number children, so `Uploading ${done} of ${total}` and `{done}` both work, but not
numbers inside a nested element. A toast's own `animateNumbers` overrides the `Notifier` setting.
Nothing animates on first render or under `prefers-reduced-motion`. Use `Toast.Number` in a custom
layout for one number that always rolls.

```tsx
<Notifier animateNumbers />

const id = notify({ title: 'Uploading 0 of 120', progress: 0, duration: 0 })
notify.update(id, { title: 'Uploading 45 of 120', progress: 37 })
```

### Icon

`shape`: `'bare'` (20px glyph colored by the status, the status default), `'box'` (36px
bordered square, the custom icon default), `'ring'` (glyph with two concentric rings, opt-in)
or `'circle'` (28px tinted circle with a plain mark, opt-in). `node` replaces the glyph.
Inside a toast, tokens are readable as CSS variables, so a custom glyph can use
`style={{ color: 'var(--ntf-accent-text)' }}`.

### Avatar

`badge`: `'online' | 'away' | 'busy' | 'offline'`. Without `src`, `fallback` renders in the
avatar (for example initials). `shape`: `'square'` (default) or `'circle'`.

### Actions

```ts
type ActionConfig = {
    label: ReactNode
    onClick?: (toast: { id; dismiss; update }) => void | Promise<unknown>
    variant?: 'text' | 'outline' | 'filled' // default 'text'
    color?: 'default' | 'muted' | 'accent' // default 'default'
    dismiss?: boolean // default true: the toast closes after onClick
    href?: string // renders an anchor
    disabled?: boolean
    pending?: boolean // keeps the loading state, aria-busy, ignores presses
    labels?: { loading?: ReactNode; success?: ReactNode; error?: ReactNode }
}

An `onClick` that returns a promise makes the action stateful: `loading` with a spinner while it
runs, then `success` with a check for 900ms before the toast dismisses (when `dismiss` is true),
or `error` with a cross for 1.6s before it returns to idle with the toast still open. `labels`
sets the text per state; the label, glyph and width crossfade. Presses during a state are
ignored. A sync `onClick` dismisses right away as before.
```

Text actions have no padding and sit flush with the text. Outline and filled actions are
34px tall buttons. Filled with `color: 'accent'` is the primary button. Filled with the
default color is a neutral button.

### Duration

An explicit `duration` wins, and `0` means persistent. Otherwise a toast is persistent when
`status` is `'loading'` or when `progress` is below 100 or `null`. Every other toast uses the
`Notifier` duration (default 5000). `update` keeps the running timer unless the patch sets
`duration` or the toast switches between persistent and timed, in which case the timer
starts again. Passing `duration` in a patch always restarts it. A timer starts when `Notifier`
first shows the toast, so a toast opened before `Notifier` mounts, or in a tab that is hidden,
does not run out unseen.

## Update in place

```tsx
const id = notify({ icon: <CloudUpload />, title: 'Uploading', progress: 0 })
upload.on('progress', (percent) => notify.update(id, { progress: percent }))
upload.on('done', () => notify.update(id, { title: 'Done', progress: 100 }))
```

At 100 the toast starts its normal timer and closes. To clear a slot, patch it with
`undefined`, for example `notify.update(id, { actions: undefined })`.

## Promise

```tsx
await notify.promise(save(), {
    loading: 'Saving',
    success: (data) => ({ title: 'Saved', description: data.name }),
    error: (error) => ({ title: 'Could not save', description: error.message }),
    id: 'save' // optional
})
```

Each message is a string, a `ToastInput`, or a function of the value or the `Error`. Icon,
avatar, meta, description, progress and actions from the loading toast are cleared when the
promise settles. The call resolves with the promise's value and rethrows its error. A call that
is not awaited leaves no unhandled rejection. `maxVisible` never replaces the loading toast.

## Primitives

`Toast` is the surface. Pass content props for the default layout, or children to build your
own. Parts read their tone, classes and dismiss handler from the toast around them.

```tsx
import { notify, Toast } from '@remcostoeten/notifier'

notify.custom((toast) => (
    <Toast tone='light'>
        <Toast.Avatar src={sienna.src} badge='online' />
        <Toast.Body>
            <Toast.Title meta='2 mins ago'>Sienna Hewitt</Toast.Title>
            <Toast.Description>I have finished adding my notes.</Toast.Description>
            <Toast.Progress value={60} label />
            <Toast.Actions aside='optional trailing content'>
                <Toast.Action variant='outline'>Dismiss</Toast.Action>
                <Toast.Action variant='filled' color='accent' onClick={reply}>
                    Reply
                </Toast.Action>
            </Toast.Actions>
        </Toast.Body>
        <Toast.Close />
    </Toast>
))
```

| Part | Props |
| --- | --- |
| `Toast` | `tone`, `width`, `className`, `classNames`, `style`, `animateNumbers`, `children`, and every content field |
| `Toast.Icon` | `shape`, `status`, `node`, `children` |
| `Toast.Avatar` | `src`, `alt`, `fallback`, `badge`, `shape` |
| `Toast.Body` | Column for text, progress and actions |
| `Toast.Title` | `meta` |
| `Toast.Description` | none |
| `Toast.Progress` | `value` (`null` is indeterminate), `label` |
| `Toast.Actions` | `aside` |
| `Toast.Action` | `variant`, `color`, `onClick` (may return a promise), `labels`, `dismiss`, `href`, `disabled`, `pending` |
| `Toast.Number` | `value`, `locales`, `format` (`Intl.NumberFormatOptions`), `className`. Always rolls, whatever `animateNumbers` is |
| `Toast.Close` | `label` (aria-label, default `labels.close` of `Notifier`, else `Close`) |

`useToast()` returns `{ id, tone, dismiss, update }` for the toast it is rendered in. Outside a
toast it returns no-op handlers, so `Toast` can also be rendered on its own, for example in docs.
A standalone `Toast` adds the same single stylesheet to the head.

## Notifier props

| Prop | Default | Notes |
| --- | --- | --- |
| `position` | `'bottom-right'` | `top-left`, `top-center`, `top-right`, `bottom-left`, `bottom-center`, `bottom-right` |
| `tone` | `'light'` | `'light'`, `'dark'` or `'auto'` (follows `prefers-color-scheme`) |
| `maxVisible` | `3` | Per position. The oldest open toast is dismissed with reason `replaced`. Loading toasts, unfinished progress and `duration: 0` are never replaced |
| `duration` | `5000` | `0` keeps every toast open unless it sets its own |
| `swipe` | `true` | Swipe towards the screen edge to dismiss |
| `pauseOnHover` | `true` | Holds every timer while the pointer is over a toast, and while the tab is hidden |
| `hotkey` | `'alt+t'` | Focuses the newest open toast. Modifiers and one key joined by `+`, or `false` to turn it off |
| `close` | `true` | Close button default |
| `stack` | `false` | Overlapping stack that expands on hover |
| `offset` | `24` | Number, or `{ x?, y? }` |
| `gap` | `12` | Pixels between toasts |
| `theme` | none | See Theming |
| `labels` | none | `{ region?, close? }`: the region's `aria-label` (default `Notifications`) and the close button's (default `Close`) |
| `animateNumbers` | `false` | Rolls the digits of numbers in the title, meta, description, progress label and actions aside when they change. See Number animation |
| `layer` | `false` | `true` puts the stylesheet in the cascade layer `notifier`, a string names the layer. See Tailwind |
| `nonce` | none | CSP nonce for the stylesheet |
| `className` | none | Added to each position container |

Mounting a second `Notifier` logs a warning in development.

## Keyboard

`Notifier` sits at the end of the page, so the `hotkey` (default `alt+t`) moves focus to the newest
open toast. Tab then reaches its actions and close button. `Escape` dismisses the focused toast
and returns focus to where it was before. A toast never closes while focus is inside it: the
timer holds on focus and resumes with the time left on blur, whatever `pauseOnHover` is. Toasts
that ask for a decision should use `duration: 0`.

## Theming

Tokens are CSS custom properties, one set per tone. Set them with the `theme` prop or in CSS.

```tsx
<Notifier
    theme={{
        font: 'Geist, sans-serif',
        radius: 16,
        width: 420,
        dark: { background: '#0b0b0c', accent: '#7c6cff' },
        light: { accentText: '#4338ca' }
    }}
/>
```

```css
:root {
    --ntf-dark-background: #0b0b0c;
    --ntf-light-accent: #5f5afa;
    --ntf-radius: 16px;
}
```

Token names: `background`, `foreground`, `body`, `meta`, `muted`, `icon`, `divider`, `border`,
`shadow`, `accent`, `accentText`, `accentForeground`, `track`, `control`, `controlBorder`,
`controlForeground`, `controlShadow`, `controlHover`, `success`, `error`, `warning`, `info`.
The variable for token `accentText` in tone `dark` is `--ntf-dark-accent-text`. Non-tone
variables: `--ntf-font`, `--ntf-radius`, `--ntf-width`, `--ntf-padding` (default 16px, the
inner padding, which also places the close button) and `--ntf-gap` (default 16px, between the
icon and the text).

Inside a toast the active tone's tokens are also available without the tone, such as
`var(--ntf-foreground)` and `var(--ntf-accent-text)`.

## Tailwind

Tailwind v4 puts its utilities in a cascade layer, and unlayered CSS always beats layered CSS,
so by default a utility in `className` or `classNames` cannot override a property the toast
stylesheet sets. Put the stylesheet in a layer and order it below the utilities:

```tsx
<Notifier layer />
```

```css
@layer theme, base, notifier, components, utilities;
@import "tailwindcss";
```

Only use `layer` when the page's resets are layered too. Unlayered CSS, such as a
`button { padding: 0 }` reset or Tailwind v3's preflight, beats a layered stylesheet and
strips the toast's padding, borders and button backgrounds.

## Recipes

Status toast with text actions:

```tsx
notify({
    tone: 'dark',
    status: 'success',
    title: '“Amélie Laurent” details updated',
    description: 'Your changes have been saved and your profile is live.',
    actions: [{ label: 'Dismiss', color: 'muted' }, { label: 'View profile' }]
})
```

Icon box with outline and filled buttons:

```tsx
notify({
    tone: 'dark',
    icon: <Codepen />,
    title: 'A new update is available',
    meta: 'v4.2',
    description: 'Includes the all new dashboard view.',
    actions: [
        { label: 'Skip this update', variant: 'outline', color: 'muted' },
        { label: 'Install now', variant: 'filled' }
    ]
})
```

Undo:

```tsx
notify({
    title: 'File moved to trash',
    actions: [{ label: 'Undo', color: 'accent', onClick: restore }]
})
```

## Rules for generated code

- Mount one `<Notifier />`. Do not import a stylesheet.
- Keep the id returned by `notify` when the toast will be updated or dismissed later.
- Use `status: 'loading'` or `progress` for work in flight. Do not set `duration` on them
  unless the toast should close by itself.
- Use `notify.update` to change an open toast. Do not open a second toast for the same job.
- Reuse a fixed `id` for one toast per topic. Each call replaces the toast's content.
- Use `color: 'accent'` with `variant: 'filled'` for the primary action.
- Put layout the slots cannot express in `notify.custom` with the `Toast` parts.
